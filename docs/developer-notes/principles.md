# Principles

I feel kinda weird even writing this out. It's a new thing for me to be writing like
this in a code repo, but I really think the key to succeeding in these personal
projects moving forward will be to slow down and truly own the entire thought process.
Too many times I've been in endless loops with Claude or GPT, stumbling over random
thoughts for hours before eventually realizing I hadn't done any actual thinking of my
own. These LLM's are unbelievably good at convincing you that you're on the right track,
and you're only one or two more prompts away from having the perfect implementation plan
for your next project. This is fine, of course, if your goal is simply to finish the
task and move on to the next project. What I've come to realize with myself, however, is
that the end goal was never truly the part of this process that brought me the most
happiness. It was the thinking - the brainstorming, the struggling, the "a-ha" moments 
when I was able to get around a blocker using only my own creativity and thinking. I
utilize AI tools heavily in my day-to-day work, and my usage habits there have slowly
been sneaking into my own personal projects to the point that I no longer have been
allowing myself to enjoy the parts of this process that I love most. Because of this,
there is one guiding principle that will drive this project throughout its' entirety:

There will be no single line of code included in this project that was written with the
use of AI tooling.

This is not to say that I am completely anti-AI. I think AI is a fantastic tool, and
it's a great resource to use for plenty of things. I love building out tools and
workflows that utilize this new technology as best I can. But this project is the
perfect situation for me to take a step back and take complete ownership over the final
product. If the end result is a fantastic tool, I want to be selfish and say it was me
who wrote it, and not an LLM. If there are issues with it, I want to be responsible for
digging into them and figuring out what went wrong and how to fix it. By taking this
stance and disallowing AI-generated code from entering the codebase, I hope to take
pride and ownership in crafting the best product that I can.

On another note, there's an additional guiding principle that I want to enforce in this
codebase, and it applies both to myself and anyone who happens to glance through here:

I don't intent to write perfect code. I don't even plan on writing very good code. My
mission is to write code that works well enough to accomplish all of the goals I set out
to accomplish. That's it. 

This codebase is NOT going to be elegant. It's not going to be something to reference in
the future for novel approaches. It's going to be ugly. And it's going to have a lot of
eyebrow-raising lines. But it's going to work. And I'm going to take ownership of it's
working, and that's going to be good enough for me.

This document, like all of the documents in this developer-notes directory, is going to
be a living document. This directory is really going to serve as a slow-moving technical
blog as much as it is a source of documentation for the project. I hope to continue
adding to these principles as I become more opinionated.
